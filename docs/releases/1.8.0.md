# 1.8.0 · dsh-purge-零甲

## 这一版做了什么

1. **零甲层 #97–#100**：四个出模型前的出口做整句删除，而不是改写限制句。
   - #97 `ZERO_ARMOR_PROMPT_SINK`：`renderPrompt` / `joinContextSections` 出口洗甲（system prompt + runtime context）。
   - #98 `ZERO_ARMOR_MESSAGES_SINK`：`deriveMessages()` 出口按 `source.kind` 丢 developer 与非用户来源的 user 消息。
   - #99 `ZERO_ARMOR_TOOLS_SINK`：`buildRequest` 冻结 header 前洗工具 schema（含参数级 description 下钻）。
   - #100 `ZERO_ARMOR_HISTORY_SINK`：assistant 历史里的拒绝句按句删除；默认不删整条消息（保 roles 交替）。
2. **`obsoleteWhenAbsent`**：功能被上游删掉时判 `na`，不再永久 `drifted`；已给 7 条补丁声明符号。
3. **自测**：engine 18 条、zero-armor 19 条；`npm run selftest`。

## 实测（DSH 0.2.2-rc.5 / iOS web profile）

- 补丁：92 条定义 → 69 条参与判定 → 64 应用 / 5 跳过 / 0 漂移。
- 零甲锚点：`dsh-system-prompt` 2 处、`dsh-agent-loop` 2 处，全部 `applied`。
- 文本审计：263 条模型可见文本，含甲 11 → 净化后残留 0。
- 运行态探针：`messages 52→49 dropped 3`；`history` 事件按需写入。

## 已知限制

- `historyScrubDrop` 默认关：整条删除会造成相邻同角色消息，Anthropic 形状的端点可能报 roles 必须交替。
- `zeroArmorMode: "void"` 只保留工具描述首行，模型需要自己推断参数语义，长任务下成功率会降。
- L5（模型权重里的对齐倾向）不可达，只能靠上下文压制。

## 升级注意

从 1.7.20 升级：先 `purge-lingjia revert` 撤宿主补丁，再装本版并重新 `/purge apply`——
零甲的 4 处锚点必须按新宿主原文重打，直接覆盖安装会留下旧锚点。
